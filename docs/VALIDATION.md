# v1.1.1 验证记录

- 131 项 Python 测试通过。新增回归覆盖 JSON 界面导入、旧 ZIP 导入、本机路径保存、异常 appearance 类型及两种 ZIP 导出：导入/迁移清空外来 DeepSeek 路径，正常启动仍保留本机数据目录；语音字幕、动画、字体、尺寸及其他设置保留。

这是实际 EXE 与连接入口的联调，事件与余额为模拟数据。本轮没有重新登录真实账户或发起真实计费任务；之前的真实账户/任务验证见 [v1.1.0 记录](https://github.com/Doya16/dsh-shorekeeper/blob/v1.1.0/docs/VALIDATION.md)。

## v1.1.1 源码对应关系更正

重新下载公开 npm 包，并直接与发布提交 `f0dcc2121a263b09abc6813487d03c58c2fe207b` 的 Git blob 比对，确认 npm 元数据缺少 `gitHead`。14 个文件中 9 个逐字节相同；`lib/client.js`、`lib/index.js`、`locale/en.json`、`locale/zh.json` 和 `runtime-manifest.json` 的差异仅为 CRLF/LF 换行，归一化换行后内容相同。之前“与发布源码逐字节一致”的表述不准确，实际比较对象是本地工作目录。

v1.1.1 的公开发行包保持原样。后续版本按 [npm 发布流程](BUILD.md#npm-发布与源码对应) 从已推送的干净 Git clone 直接发布，发布前逐文件检查 Git 原始字节，发布后校验公开 `gitHead` 和实际下载包。

发布流程修正后的 18 项 Node 测试通过，其中 6 项新增回归覆盖精确字节、Git 显示干净时的 CRLF 差异、未提交修改、忽略文件混入、打包钩子及过期 gitHead。另从公开 GitHub 重新 clone，实际执行目录发布到仅监听本机的测试 registry：确认发布钩子执行、npm 自动写入正确 gitHead、生成包内 14 个文件与该提交逐字节一致。发布后校验工具能拒绝缺少 gitHead 或仅换行不同的包。本次流程验证没有重新发布 npm 正式版本。
